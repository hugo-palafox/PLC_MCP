# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]

### [2026-02-14]
#### Added
- Sum Read (Batch Reading) implementation in `beckhoff.py` using `pyads.Connection.read_list` for high-efficiency OEE monitoring.
- Symbol caching logic in `TwinCATDriver` to prevent expensive re-uploads in large PLC projects.
- Substring filtering (`filter_match`) in `list_plc_tags` tool for easier tag discovery.
- Enhanced tool schemas in `server.py` with descriptive parameters for better LLM integration.
- Implemented `ollama_host.py`: A Python-based MCP Client that bridges the PLC bridge with a local Ollama instance (e.g., Llama 3.2) for offline natural language interaction.
- **Autonomous Dashboards**: Created `dashboard_generator.py` and the `generate_dashboard` MCP tool to programmatically generate Grafana JSON layouts using `grafanalib`.
- **AI-Powered Dashboard Generator**: Created `ai_dashboard_generator.py` that uses DeepSeek LLM to intelligently analyze PLC tags and generate optimized Grafana dashboards without hardcoded templates. Features automatic panel type selection, intelligent layout optimization, and tag categorization.
- **AI-Generated Dashboard Visualizations**: Completely rewrote web dashboard to use AI (llama3.2) for generating custom HTML/CSS/JavaScript visualizations. AI analyzes user queries and PLC data to create dynamic gauges, charts, animations, and custom UI components. Removed all hardcoded templates - every visualization is uniquely generated by AI based on context. Includes template variable replacement to inject actual PLC values into AI-generated code.
- **Multi-Machine Support**: Web dashboard now supports multiple machines with dropdown selector. Auto-discovers all machine configurations in `plc_settings/` directory. Each browser session can view different machines independently with session-based tracking.

#### Changed
- **Switched to llama3.2**: Replaced deepseek-r1 with llama3.2 for AI visualization generation due to significantly faster response times (30-60 seconds vs 120+ seconds timeout). Simplified prompts for optimal performance.
- **Template Variable Replacement**: Added frontend logic to replace AI-generated template strings (e.g., `{{ data.Global2.fOEE_Overall.toFixed(4) }}`) with actual PLC values from metrics_data.
- Enhanced system prompt to leverage DeepSeek's step-by-step reasoning for analyzing PLC data patterns and providing insights.
- Updated `generate_dashboard` MCP tool to support both AI-powered (default) and template-based dashboard generation via `use_ai` parameter.
- **Dynamic Dashboard Filtering**: Web dashboard now filters metrics based on user queries (e.g., "show only parts produced" displays only production-related metrics). Supports OEE, Production, Hourly trends, Status, and Time categories.

### [2026-02-13]
#### Added
- `README.md` created by merging functional definitions and setup guides.
- New `tests/` directory for validation scripts.
- New `tools/` directory for discovery utilities.
- Standardized absolute paths in `server.py` and `run_server.ps1` to facilitate LLM/Agent management of the MCP.

#### Changed
- `server.py` polished: Added logging, improved configuration loading using `pathlib`, and enhanced error management.
- `server.py` re-engineered: Implemented dynamic machine-specific configuration loading from the `plc_settings/` directory.
- `run_server.ps1` updated: Now automatically detects and uses the `.venv` virtual environment if present.
- Improved directory structure: Moved `test_*.py` and `discover_tags.py` to appropriate subfolders.
- Transitioned metadata: Created `plc_settings/Testing_Machine.json` with a structured `MachineName`/`Type`/`Tags` schema and removed the flat `tags.json`.
- Updated configuration logic: Switched from `AMS_NET_ID` to `IP_Address`. Implemented automatic `.1.1` suffixing for Beckhoff PLCs.
- Fixed modularity: Converted `drivers/` and `tests/` into proper Python packages with `__init__.py` and standardized `sys.path` handling in test scripts.
